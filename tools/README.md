# tools/ — Dev tooling (never deployed)

Headless-Chrome test harnesses and helpers for this project. Everything in here
is dev-only; `game/` stays deployable-only and never requires `tools/` at runtime.

Run any tool from anywhere with `node` (Node >= 22 — uses global `fetch` +
`WebSocket`). No npm install needed. `CHROME_PATH` env overrides the Chrome
binary.

## Files

| File | What it is |
| --- | --- |
| `headless.js` | Shared harness: serves `game/` over HTTP, boots headless Chrome on a **unique temp profile**, returns `{ evalv, evalp, navigate, close, port }`. Also exports `serve()` (the static server alone, for tools that drive their own browser), `check(name, ok, info)` (prints `PASS`/`FAIL`), `sleep`, `getFails()`. It also exports **`skip(name, why)` / `getSkips()`** for the rare check that cannot run because the *environment* lacks a capability — a skip prints `SKIP`, is counted, and is never a pass. Use it only for a genuine environment limit (today: `racing3d_smoke.js`, whose race needs WebGL), never to paper over a failing assertion or to stub out the code under test. **`killChromeByTag()` has a Windows (`pwsh`) and a POSIX (`pkill -f user-data-dir=<tag>`) branch** — the Windows-only version silently leaked every browser on Linux, and 21 orphans starved the suite enough to make `touch_interruption` hang 8+ minutes on its first game instead of finishing in 100 s. If the suite gets slow or a check "only" fails under parallelism, run `pgrep -f chromium | wc -l` before touching the test. `start()` also takes an optional `dpr` (default 1) to compare pixel cost — used by the racing3d perf measurements. Kills only this run's Chrome on `close()` — stale-Chrome profile locks were the historical "Chrome did not start" cause. Use `evalv` for sync expressions, `evalp` when the expression returns a Promise. **The Chrome debug port comes from `freePort()` (`listen(0)`), never from arithmetic on the origin port** (R7/task 167). It used to be `httpPort + 100 + Math.random()*1000`, and that was the real cause of the intermittent "Chrome did not start" that had been blamed on host load: Windows hands out ephemeral ports around 49582-57766, and Hyper-V/WinNAT reserves 17 blocks inside that span (`netsh interface ipv4 show excludedportrange protocol=tcp` listed 52240-52339, 53865-53964, 55973-56672, …), so roughly **9%** of derived ports were unbindable — Chrome could not listen on one at all, and no amount of extra patience fixes an unbindable port. Negative-tested: reverting just that line reproduces the failure on a port that sits inside an excluded range. **`close()` is `async` and must be awaited** by any tool that starts more than one browser in a process: it waits for the debug port to go quiet before returning, and deletes the profile dir (~20 MB, otherwise leaked into `%TEMP%` forever — 1503 of them had accumulated, 32 GB). The four `touch_interruption_*` shards boot four browsers each and were the tools that raced it. |
| `run_all.js` | **Start here.** Parallel smoke-suite runner (default 4 workers, or `$RUN_ALL_CONCURRENCY`) with a per-tool `PASS`/`FAIL` table, per-tool seconds, a `--- slowest ---` block, a total ms/check line, and a non-zero exit code. Safe to parallelize because every smoke already uses its own Chrome profile + debug port. `--game <substr>`, `--since <sha>` (git-diff → static file→smoke map; `game/shared/*` and unmatched files expand to the whole battery), `--watch` (mtime-poll of `game/**`, re-runs only affected smokes), `--concurrency N`, `--sequential` (= concurrency 1), `--resume [dir]` (skip smokes that already passed; each smoke is checkpointed as it lands, default `$TMPDIR/run_all_resume` — this is what makes a run survive a host that kills the process on a resource spike, see task 156), `--list`, `--list --json` (the battery as a JSON array — **CI's matrix is generated from this**, so a newly added smoke cannot be silently left out of the workflow), or positional smoke names. A smoke that exits non-zero with **0 checks** never got its assertions run (Chrome failed to boot under parallel load) — those are retried twice automatically. The `game/games/<file>` → smoke mapping is **derived** from the registry plus "which pages load this module", not hand-written (R7/task 167 replaced a `GAME_SMOKE` table that had already drifted from `app-registry.js`); the few module/config files with no registry id of their own (`adventure.js`, `kids_games.js`, `racing-config.js`, `racing3d-config.js`) are named explicitly and `guards/games_map_negtest.js` proves each still resolves and that breaking a shared-module reference actually loses coverage. |
| `check_syntax.js` | Read-only `node --check` over every `.js`/`.mjs` in `game/` + `tools/`, exported as `runSyntax()` and runnable alone. **Split out of `check_all.js` (task 164) so CI's fast job can check syntax without running the battery** — `check_all.js` calls the same function, so there is one implementation and one output. Add `--quiet` for exit-code only. |
| `check_fast.js` | **The read-only fast gate (R5/task 165).** 6 stages, ~9 s: `check_syntax.js` → `validate_pages.js` (registry/metadata) → `validate_workflow.js` → `validate_generated.js` → `validate_offline.js` → `hub_smoke.js`. **Writes nothing** — it never regenerates or syncs. Exists so the gate has *one* definition: CI's `fast` job is a single `node tools/check_fast.js` call rather than four YAML steps that can drift from the local list. A stage that exits non-zero with **0 checks** is a Chrome boot crash (this host gets killed on resource spikes), so it is retried up to 2× rather than reported as a failure. Add `--quiet` for exit-code only. |
| `runtime_error_smoke.js` | **R8/task 169 runtime-error gate.** Visits the hub and every registry page, fails on captured runtime exceptions, `console.error`, unhandled rejections, same-origin resource failures, and relevant service-worker registration warnings; then deliberately injects each failure type and asserts the harness catches it. It is a normal `*_smoke.js`, so the battery and CI matrix pick it up automatically. |
| `validate_workflow.js` | **CI-topology guard (R5/task 165), 11 read-only checks over `.github/workflows/ci.yml`:** every `tools/*.js` the workflow invokes exists; every `needs.<job>.outputs` read has a **direct** `needs` entry (`needs` exposes direct dependencies only — an indirect read yields `''`, `fromJSON('')` throws, and the matrix silently never runs while the pipeline looks green); no tabs; no CR; balanced `${{ }}`; every job declares `runs-on`; every step has `uses:`/`run:`; the matrix is generated from `needs.setup.outputs`; `fail-fast: false`; setup derives the battery from `run_all.js --list --json`; `extended` is manual/schedule only. The last three are what make R4's fixes permanent instead of a one-time edit. Negative-tested: 5 deliberate mutations each fail. The no-CR check relies on `.gitattributes` pinning `.github/workflows/*.yml` to `eol=lf`. |
| `validate_generated.js` | **Generated-artifact freshness (R5/task 165), the command the roadmap asked for.** 4 read-only checks: the committed `docs/` mirror has exactly the same file set as `game/` (208 files — a file present on only one side is a failure), every pair is **canonically** byte-identical (LF-normalised, so a CRLF checkout is not a false alarm), and `game/sw-cache-list.json` equals what `generate_sw_list.js --stdout` produces (207 entries). **It reports, it never repairs** — every failure names the explicit command that fixes it (`sync-docs.sh` / `generate_sw_list.js`). This is the guard for "edited `game/` and forgot to sync", which used to ship a stale site silently; `sw_update_smoke.js` cannot catch it because both the stale `docs/` and the fresh `game/` are internally consistent. Negative-tested. |
| `check_release.js` | **Read-only release gate (rewritten in R5/task 165).** `check_fast.js` → the whole battery **through `run_all.js`** (keeping its parallelism, boot-crash retries and `--resume`) → with `--release`, two **advisory** stages: `offline_smoke.mjs` (known red until R6) and `axe_check.js --report` (informational until R10). Advisory stages print their real exit code and are labelled `ADVISORY`, never dressed up as a pass. `--fast` skips the battery; `--concurrency/--resume/--game/--since` pass through. **The contract is enforced, not promised:** it fingerprints `docs/`, the cache list, the manifest and the ZIP before and after, and exits non-zero naming whatever changed. The previous version was three commands wearing one name — its "syntax" step called `check_all.js` (the entire battery), it ran `sync-docs.sh` (rewriting all of `docs/`), and it ran `build_offline.js` (regenerating the manifest + ZIP) — so a stale artifact could never be reported, only quietly fixed. Not a CI job: it re-runs the battery the pipeline already ran in parallel, one leg per job. |
| `registry.js` | **Shared app-registry loader (R7/task 167).** One place that knows how to read `game/data/app-registry.js` (which is browser script, so it is evaluated with a mock `window`) and derive from it: `all`, `children`, `parents`, `byId(id)` (an entry; `byId()` returns the map), `byRoute`, `roleOf`, `routesByGroup`, `allHubRoutes`, `loadRegistry`, `RETIRED_ROUTES`. Every tool reads the app list through it — `run_all.js`, `offline_smoke.mjs`, `hub_smoke.js`, `axe_check.js`, `play_matrix.mjs`, `touch_interruption_core.js`, `screenshot.js`, `validate_pages.js`. Before this, seven tools each had their own copy of the loader and their own hardcoded app list. |
| `guards/registry_guards_negtest.js` | **Negative test for the registry contract checks in `validate_pages.js` (R7/task 167).** 12 mutations of `game/data/app-registry.js` / `game/index.html`, each of which must produce a non-zero exit **and** the guard's own message (a non-zero exit alone would let an unrelated failure be credited). Covers duplicate id/route/hubOrder, a route with no hub button, a `back` id no page contains, a `start` global no script defines, missing hubOrder, a path outside `pages/`, an entry with no id, a page missing from the registry, a retired route restored, and a retired hub button un-hidden. Every mutation must stay **syntactically valid** — three early cases "passed" only by breaking the JS parse, which is a crash, not a contract report. Restores the files afterwards; not a `*_smoke.js`, so `run_all` ignores it. |
| `guards/route_contract_negtest.js` | **Negative test for `route_contract.js` (R7/task 167).** Six wrong-wiring forms (hardcoded route table in `navigation.js`, a page not loading `app-registry.js`, a self-wiring page given a back button it does not have, …) each must be detected, plus a positive control on the real wiring. `route_contract.js` replaced ten smokes' hand-written greps for the removed route tables — those assertions were written against code that no longer exists and passed vacuously. |
| `guards/games_map_negtest.js` | **Negative test for the derived game-file → smoke mapping in `run_all.js` (R7/task 167).** Proves `smokesForGameFile()` reproduces the coverage of the hand-written `GAME_SMOKE` table it replaced (a second app list that had already drifted: `candy.js` vs the registry's `matching_game`), that every per-game smoke is reachable, that no registry entry names a missing smoke file, that every declared shared/engine module names at least one real smoke, and — via a real edit of `pages/dino.html`, restored afterwards — that breaking a shared module reference actually **loses** coverage. | `check_all.js` | The one-command validation ritual: `node --check` over every `.js`/`.mjs` in `game/` + `tools/` (via `check_syntax.js`) → the full smoke battery → optional `--docs` (`tools/sync-docs.sh`, required whenever `game/` changed) / `--offline` (`tools/build_offline.js` + then `validate_offline.js`). | `parent_smoke.js` | The parent area (R12/task 163) — 6 checks: the four actions (offline download, update check, reset progress, audio test), the **manual ZIP link** (present, correct href, `download` attribute), the **app version** resolved from `manifest.json` as a real `x.y.z`, a **live connection status** (Онлајн/Офлајн), the back button, and the audio test being wired. | `sw_update_smoke.js` | Service-worker update-path correctness (R3/task 154) — 8 checks, **served under a deliberate subpath `/some/deep/prefix/`** so any deployment-path assumption fails loudly. Asserts the worker registers and controls the page, that `scriptURL` proves the scope follows the subpath, that the offline manifest is cached under its **scope-relative** URL, and the three update-detection cases: no server change → `changed: 0`; a changed file is detected **and named**; a **removed** file is still reported. | `validate_offline.js` | **Offline inventory validator (R2/task 153).** Runs 10 checks over the three inventories — `sw-cache-list.json`, `offline-manifest.json`, and the ZIP: every cache entry exists; no entry points at a retired file; manifest keys == cache-list keys exactly; manifest sha256 **and** size match the real bytes; **every local runtime dependency referenced by an HTML page is in the cache list** (this is what would have caught the R1 `racing-config.js` bug at source); no `docs/`/`resources/` leakage; caregiver docs packaged-but-not-cached; **generation is deterministic** (invokes `generate_sw_list.js --stdout` and requires canonically identical output — see `manifest_hash.js` below, and why a raw byte compare was machine-dependent); list is sorted. **Task 165 made this read-only, and the change was a real bug, not a cleanup:** it used to re-run the generator in *write* mode and then compare the file with itself, so the "validator" rewrote `game/sw-cache-list.json` on every run, **silently repaired a stale cache list instead of reporting it**, and left a phantom ` M game/sw-cache-list.json` in the worktree on every run on this CRLF checkout. Wired into `check_all.js --offline`, so a bad manifest fails the ritual instead of shipping. **Known enforced exception:** `offline-manifest.json` must NOT list itself — it is written after hashing, so a self-entry held the hash of the *previous* manifest, which made `sw.js checkForUpdates()` report it as changed on every single update check. |
| `manifest_hash.js` | **Canonical-bytes hashing (task 164), shared by `build_offline.js` and `validate_offline.js`** so the builder and the validator can never disagree about what a hash means. Text files are hashed as **LF**; binary files (NUL byte in the first 800 bytes) byte-for-byte. Without it the manifest was hashed off raw work-tree bytes, so it depended on the machine that built it: `.gitattributes` deliberately pins **only** `.github/workflows/*.yml` to `eol=lf` (task 165, for the workflow's no-CR check), so `game/` and `docs/` are still CRLF on disk here and LF in git/CI — the committed manifest was genuinely mixed (13 of 63 text entries hashed as CRLF, 50 as LF). It verified by luck, but the next rebuild here would have baked CRLF hashes in and made every Linux checkout, plus the parent's «Проверити ажурирања», report the whole app as changed. Regenerating with the canonical form reproduces the committed manifest byte-for-byte. |
| `offline_smoke.mjs` | True offline browser test (not part of the 19-tool battery). | `play_matrix.mjs` | Playwright device matrix: 5 viewports (phone portrait/landscape, tablet portrait/landscape, desktop) × engines (chromium via system Chrome, webkit) × pages. | `screenshot.js` | Captures the hub and every `screenshot:true` registry page at five fixed viewports (17 surfaces × 5 = 85 PNGs). ## Rules / gotchas

- **Stale assertions:** when a check fails, first read the live page state printed
  in the FAIL info and decide whether the *game* or the *assertion* is wrong.
  Fix assertions to the observed truth — never change `game/` to satisfy a test.
  A count taken from a source file (e.g. a hub tile count) should be **derived**
  in the test, not hard-coded, or the next added game re-breaks it.
- **`game/shared/main.js` boots each standalone page exactly once** via a
  `started` guard. Do not remove it and do not add a second call site: start
  functions bind click/pointer listeners, so booting twice doubles every
  interaction (that bug made one ➡️ tap advance 3 scenes).

- **Deployment:** `game/` is the single source of truth; `docs/` is only the
  published copy. On every change to `game/`, run `tools/sync-docs.sh` (it
  deletes `docs/` and re-copies `game/`) and push to `main`. Never edit
  `docs/` by hand.

- Always test over HTTP, never `file://` — `file://` breaks audio, the kitty
  iframe, and throws Unsafe-attempt warnings. `headless.js` serves `game/`
  automatically.
- Each `start()` uses a fresh unique Chrome profile, so parallel harnesses
  cannot collide; `close()` kills that run's Chrome by profile tag. If a run is
  interrupted and a later run says "Chrome did not start", kill stale Chrome:
  `Get-Process chrome | Where-Object { $_.CommandLine -match 'pkv-' } | Stop-Process -Force`.
- `celebration.js` caches its overlay element in a closure — a harness must hide
  overlays by removing the `.show` class, never by removing the element.
- `window.__adv` (adventure engine debug handle) exposes `cameraX`, `lastHitAt`
  etc. as **getter-only** — assignments silently no-op (and throw in strict
  mode). Reset state with `a.loadWorld()` instead; the obstacle-hit checks must
  wait ≥1100 ms after `loadWorld()` for the `lastHitAt` cooldown to expire.
- `tracing_probe.js` needs the `window.__traceDebug` hook that `tracing.js`
  exposes (`matchResult` / `refGrid` / `inkGrid`) — do not delete it.
- Matching rule to re-verify after touching `tracing.js` constants:
  pass = `coverage >= MIN_COVER && near >= MIN_NEAR && ink <= MAX_INK`, where
  `near` is the fraction of ink cells within 2 grid cells of the guide line.
  Measured separation: genuine traces `near ≈ 0.98–1.0`, blobs/scribbles ≤ 0.70.
