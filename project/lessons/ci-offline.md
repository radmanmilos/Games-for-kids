# Lessons: CI topology, offline manifest, service worker, release gate

Read before editing `.github/workflows`, `tools/build_offline.js`, `tools/manifest_hash.js`, the service worker or manifest, `tools/offline_smoke.mjs`, or any Release QA gate. Each entry is a past incident; text is moved verbatim from `AGENTS.md` (Footguns section, 2026-10-13 refactor).

- **CI's own topology has two silent-failure modes, both hit in task 164.** (a) A workflow can reference a tool that no longer exists — the old `ci.yml` ran `node tools/touch_interruption_smoke.js` after task 156 deleted it, so the `release` job failed on **every** push while the matrix quietly ran only 16 of 24 tools. (b) **`needs` exposes DIRECT dependencies only**: a job reading `needs.setup.outputs.x` while declaring just `needs: <downstream-job>` gets an empty string, `fromJSON('')` throws, and the whole matrix job **never runs while the pipeline still looks green** — i.e. zero game coverage reported as success. R4 fixed both (`ci.yml` job `smoke` now has `needs: [setup, fast]`), and the matrix is generated from `run_all.js --list --json` so a new smoke cannot be forgotten. R5 should promote the throwaway probe into a permanent `tools/validate_workflow.js` asserting both. When editing `ci.yml`, verify a job's `needs` list against every `needs.*.outputs` it reads, and **negative-test any new guard** — a check that cannot fail proves nothing.
- **The offline manifest is hashed over CANONICAL bytes, not work-tree bytes** (`tools/manifest_hash.js`: text to LF, binary identity), because `game/`+`docs/` are CRLF on a Windows checkout (`core.autocrlf=true`) and LF in git/CI. Hashing raw bytes made the pack machine-dependent: a rebuild on Windows would bake CRLF hashes into `game/offline-manifest.json` and then every Linux checkout — and the parent area’s «Проверити ажурирања» — would report *the whole* app as changed. Builder and validator must both go through `manifest_hash.js` so they cannot disagree. The validator’s "generation is deterministic" check compares canonically for the same reason: a raw byte compare reports a change on Windows only (CRLF worktree copy vs the LF file the generator rewrites), i.e. a gate permanently red locally and green in CI. **It now compares `generate_sw_list.js --stdout` against the committed list without writing it** — the old version re-ran the generator in write mode and compared the file with itself, so a stale cache list was silently repaired instead of reported and every run left a phantom ` M game/sw-cache-list.json` in the worktree. `.gitattributes` (added in R5) pins **only** `.github/workflows/*.yml` to `eol=lf`, because `validate_workflow.js` asserts the workflow has no CR (a CR in a `run:` block breaks the shell) and `autocrlf` would otherwise make that gate machine-dependent. Do not widen that rule to `game/`+`docs/` — canonical comparison is what covers them.
- **A build must not destroy the artifact it is replacing.** `build_offline.js` did `if (exists) unlink(zip)` *before* creating the new one, so any failure left no archive — and the very next line fails here, because `zip` is not on PATH. It now builds to `.tmp` and renames on success, and the error names the `.ps1` fallback. Never unlink an output before you can prove the replacement exists.
- **There is no offline ZIP (task 179, 2026-10-02, user decision).** Offline delivery is **the service worker**: the parent area's «Преузми за офлајн рад» caches everything in `game/sw-cache-list.json`, so there is nothing to hand-unpack. The `docs/game-offline.zip` archive, the hidden `#offline-zip` link in `parent.html`, and the ZIP step in both `build_offline.js` and `build_offline.ps1` are **gone for good** — the archive was never tracked in git, so Pages never published it and the link was a permanent 404. This **supersedes the 2026-09-30 "HIDDEN, not deleted" decision** from task 163; do not restore it. `parent_smoke.js` now asserts the link is **absent**, so it cannot creep back. **Do not hard-code the deployment path in the service worker.** This site is served by GitHub Pages from `docs/`, i.e. from a **subpath** (`https://<host>/Games-for-kids/`), so `/game/...` is simply wrong at runtime even though it is right in the repo. `sw.js` derives `APP_ROOT` from `self.registration.scope` and builds every URL from it — **use the same derived URL for the network fetch AND the `caches` lookup, and never duplicate a path string.** A hard-coded `cache.match('/game/offline-manifest.json')` shipped and made the parent area's «Проверити ажурирања» report *every* file as changed on *every* check. `tools/sw_update_smoke.js` serves the app under a deliberate subpath and pins this. The full mechanism is documented in **`project/reference/OFFLINE.md`**.
- **`offline-manifest.json` must never list itself.** It is written *after* the hashes are computed, so a self-entry can only ever hold the hash of the *previous* manifest. `sw.js checkForUpdates()` diffs the online manifest against the cached one and reports every differing key, so a self-entry made the parent area's «Проверити ажурирања» report a change on **every** check and never come back clean. `build_offline.js` excludes it and `validate_offline.js` enforces the exclusion. The file stays in `sw-cache-list.json` — `sw.js` reads it back *out of* the cache to diff against. Run `node tools/validate_offline.js` after touching the offline inventory.
- **`tools/offline_smoke.mjs` is now a real offline test (rewritten for R6), and it is the `Release QA` gate.** It runs ONE session: prime the cache online, cut the network with CDP's own `Network.emulateNetworkConditions` (commentary reader: the ENTIRE app is served from `127.0.0.1`, so "offline" must be imposed by CDP, not by a `*://*/*` proxy rule that would also kill the origin — that was the old false-green design), then play all 16 games with a per-registry trusted input, with a **negative control** (a URL that is not in the offline inventory must *fail* to load, else a bug that left the network reachable passes silently). Do not "simplify" it back into a two-profile or static-markup test. Its rewrite is why `AGENTS.md` must not be trusted as current on this tool without checking `ci.yml`'s comment or the tool header first.
- **The ZIP fallback is gone, and with it the `zip` dependency** (task 179). `check_all.js --offline` can now actually complete on a machine without `zip` installed — this was the long-standing reason it could not.
