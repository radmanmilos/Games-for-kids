# Lessons: racing3d (WebGL, pulses, reduced motion)

Read before touching `game/games/racing3d.mjs`, `game/pages/racing3d.html` or `tools/racing3d_smoke.js`. Each entry is a past incident; text is moved verbatim from `AGENTS.md` (Footguns section, 2026-10-13 refactor).

- **racing3d needs WebGL; most headless Linux hosts have none.** The harness launches Chrome with `--disable-gpu`, and on Alpine/CI there is no SwiftShader (ANGLE falls back to Vulkan and dies on `VK_KHR_surface`: *"SwANGLE failed with error EGL_NOT_INITIALIZED"*), so `getContext('webgl')` returns null, the game takes its correct "3D није доступан овде" fallback, and `window.__r3d` is never set. Software-WebGL flags (`--use-angle=swiftshader`/`swrast`, `--use-gl=egl`) and `apk add mesa-egl` were all tried and do **not** help — do not re-attempt. `racing3d_smoke.js` therefore reports the race battery as a counted `SKIP` and asserts only the fallback + config load. **Consequence: the 3D race has no automated coverage on such a host — the user must play-test it on a real device, and CI runners with GPU/SwiftShader are the only place the full battery runs.** Never "fix" this by stubbing `window.__r3d` or exiting early with a green summary: that is the same anti-pattern as the task-120 shared-audio stub, and it hides real regressions.
- **A pulse that re-triggers on every frame inside a radius has no stable sample while nearby.** The reactive-decor pulse (`racing3d.mjs:2295`) resets `pulseAge = 0` on any frame the kart is within 10 u, so the scale oscillates 1 → 1.15 forever and decays to baseline only *after* the kart leaves. `1.14095` is just `1 + 0.15·sin(phase)` — two different hosts sampled the identical value, which is what finally disproved "the decay is slow" and proved it was an oscillation. Assert a baseline only after an explicit clearance condition, using the game's own `Math.min` two-sided distance (seeking *behind* an item still counts as near, so a forward-only test passes vacuously).
- **Never assert the host's OS preference — assert the product's response to it.** `REDUCED_MOTION` is read once at module load, so no smoke can set it. `racing3d_smoke.js` asserted `decorAmp() === 0`, i.e. that the *machine* has `prefers-reduced-motion: reduce`: true on the user's Windows host, false on the Linux runner, so the check could only ever pass on one of them. The real invariant is `decorAmp === (rm ? 0 : 1)` — it still fails if the gate logic breaks, and holds on any host.
